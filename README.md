# DecisionLab

**DecisionLab** — учебная система поддержки принятия решений (СППР) для многокритериального сравнения альтернатив. Разработана по теме №7 дисциплины «Рекомендательные системы и системы поддержки принятия решений».

Приложение позволяет загрузить свою матрицу из CSV, настроить направления оптимизации и веса критериев, сравнить альтернативы несколькими методами и сохранить расчёты.

## Возможности

- **AHP (метод Саати):** попарное сравнение критериев, собственный вектор весов и контроль согласованности (CI/CR).
- **TOPSIS:** ранжирование по расстоянию до идеальной и антиидеальной точек.
- **ELECTRE I:** попарное отношение превосходства с индексами согласия и несогласия; чистый поток используется для отображения, а не как гарантия строгого полного ранга.
- **SAW:** дополнительное сравнение методом взвешенной суммы.
- **Анализ чувствительности:** проверка смены лидера при изменении каждого веса на ±20%.
- **Визуализация:** интерактивный рейтинг с выбором альтернатив, таблицы и объяснение лидера.
- **Данные:** редактирование, импорт и экспорт CSV, экспорт результатов в JSON.
- **История:** сохранение и повторное открытие расчётов в PostgreSQL.

## Быстрый запуск (Docker)

Требуются Docker и Docker Compose.

```bash
git clone https://github.com/ORBUZIK/decisionlab.git
cd decisionlab
cp .env.example .env
# Установите собственные значения POSTGRES_PASSWORD и DJANGO_SECRET_KEY в .env
docker compose up --build -d
```

Откройте **http://localhost:8080**. Приложение работает локально. API доступен через тот же адрес по пути `/api/`.

Выключить:

```bash
docker compose down
```

Удаление локальных данных PostgreSQL (необратимо): `docker compose down -v`.

> Для доступа извне требуется добавить аутентификацию, защиту API, HTTPS и безопасную конфигурацию. Текущий прототип **предназначен только для локального учебного использования**.

## Демонстрация

При первом открытии загружается пример **«Выбор IT-стажировки»**: 5 альтернатив, 4 критерия (зарплата, возможность удалённой работы, карьерный рост и нагрузка). Демонстрационные данные вымышлены.

1. Нажмите **«Рассчитать»**, чтобы увидеть TOPSIS, ELECTRE I и SAW.
2. Откройте **«Критерии и AHP»** для настройки весов, направлений и попарного сравнения.
3. Повторите расчёт и изучите вклад критериев и анализ чувствительности.
4. Нажмите **«Сохранить расчёт»**, чтобы занести сценарий в историю.

## Импорт CSV

Первая колонка — `name` (название альтернативы), последующие — числовые критерии.

```csv
name;Зарплата;Удалённость;Рост;Нагрузка
NovaTech;120;9;8;40
Quantum Labs;145;5;9;48
CloudWorks;110;10;7;36
```

Поддерживаются CSV с разделителем `;` или `,`, файлы до 1 МБ, **2–200 альтернатив** и **2–10 критериев**. Числа должны быть конечными, без пропусков. UTF-8, строка заголовков обязательна. После импорта направления всех критериев — «больше лучше», а веса одинаковы; обязательно проверьте их.

Используйте раздел «Альтернативы и данные» для экспорта текущей матрицы. Подготовленный демонстрационный CSV есть в `examples/internships.csv`.

## API

| Запрос | Назначение |
|---|---|
| `GET /api/health/` | Проверка API |
| `POST /api/analyze/` | Выполнить расчёт без сохранения |
| `GET /api/scenarios/` | Список сохранённых сценариев |
| `POST /api/scenarios/` | Создать сценарий и сохранить результат |
| `GET /api/scenarios/{id}/` | Получить сценарий |
| `DELETE /api/scenarios/{id}/` | Удалить сценарий |

Пример запроса:

```json
{
  "criteria": [
    {"key": "price", "label": "Цена", "direction": "min", "weight": 60},
    {"key": "quality", "label": "Качество", "direction": "max", "weight": 40}
  ],
  "alternatives": [
    {"name": "A", "values": {"price": 100, "quality": 10}},
    {"name": "B", "values": {"price": 150, "quality": 8}}
  ],
  "pairwise": null
}
```

При использовании AHP передайте матрицу `pairwise`, где `pairwise[i][j]` — отношение важности критерия i к j, значения взаимно обратны, диагональ равна 1. Матрица замещает прямые веса при расчётах TOPSIS/ELECTRE/SAW. `cr < 0.1` — рекомендуемый порог согласованности. Если `pairwise` равен `null`, веса берутся непосредственно из `criteria`.

## Разработка

Backend: Django 5.2 + Django REST Framework + PostgreSQL, расчёты на Python без ML-зависимостей.

Frontend: React 18 + TypeScript + Vite + D3.js, иконки Lucide.

Docker: nginx раздаёт собранную SPA и проксирует API на Django; PostgreSQL хранит историю расчётов.

Для запуска backend без Docker:

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py test
python manage.py runserver
```

Если `DATABASE_URL` не задан, для локальной разработки используется SQLite. Фронтенд при разработке:

```bash
cd frontend
npm install
npm run dev
```

Vite проксирует `/api` на localhost:8000. Сборка: `npm run build`.

## Ограничения

- Данные демонстрационного кейса синтетические, не являются данными работодателей.
- ELECTRE I — упрощённая реализация с порогами 0.65/0.35, которая допускает несравнимые альтернативы и циклы.
- AHP применяется для определения весов критериев; согласованность не гарантируется автоматически и отображается при анализе.
- Веса и критерии зависят от субъективных предпочтений пользователя, рекомендации не являются абсолютными.
- Системы учётных записей и разграничения доступа в MVP нет. Запускать публично без дополнительной защиты нельзя.
